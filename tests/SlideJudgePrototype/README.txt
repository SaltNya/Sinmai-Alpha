Sinmai-Alpha 判定数学离线原型 v2

状态
  仅供研究与对照；不进入 Sinmai-Alpha.csproj 的 src 编译范围。
  本项目本身不修改游戏；独立运行时接入位于 src/Notes/ExperimentalSlideJudge，
  由 ExperimentalSlideJudgment 控制，默认关闭。
  不能将本目录编译结果当作 Mod DLL 安装。

  dotnet run --project tests/SlideJudgePrototype/Prototype.csproj -c Release
  dotnet run --project tests/SlideJudgePrototype/Prototype.csproj -c Release -- C:\项目\SlideJudgePrototype-20261102-v2

  viewer.template.html  生成器使用的模板，不含数据；不要把它当作报告。

  使用自定义输出目录时，直接打开该目录的 report.html；源码入口对应默认目录。

结构
  ArcLengthPath.cs
    直线、圆弧保留解析长度和坐标；圆弧可跨多圈。
    变半径 PolarArc 和不透明曲线使用四分点误差/弦长约束自适应细分。
    累加每段实际长度，按距离二分查找位置；不把 t*总长作为曲线弧长。
    目前不是任意函数的严格误差证明；黑盒曲线有 64 个初始采样段，
    单精度 Touch 适配器有 .0002 坐标单位的舍入容差。
    有评估次数、段数、递归深度限制，超限报错，避免读谱无限计算。
    判定拓扑分析会合并共线同向直线，插入无意义中间点不会改变 V 门控。

  SensorRegions.cs
    区域是可替换的候选圆/多边形及其并集，绝不宣称是实体传感器边界。
    直线-圆、圆弧-圆解析求交；同一传感器连续区间合并。
    离开后再次进入同一区域会保留为不同事件。切点不生成必按区。
    ABC / ABCDE 只改变启用的区域集合，不另建一套判定数学。
    C1/C2 归为同一个物理 C，E7/E8 使用独立编号。
    预计算包围范围，跳过明显不相交的路径段。轮廓复制为只读数据，
    防止修改顶点后缓存范围失效。

  ContourRegions.cs（v2）
    使用所有键共享的方向轮廓，不按 SC 字符串或整条官谱形状查表。
    A/B 半径-角宽轮廓由少数原版直线/外圈弧的局部交点约束得到。
    直线-凹多边形、圆弧-凹多边形均按边界交点分段，不增加密集采样。
    任选容错与轮廓事件分离：A/B 径向邻近、B/C 偏心、邻接 B 方位相近，
    以及沿圆周穿越 A/B 空隙时的任选窗口。径向 A->B 不插入多余步骤。
    数值 55、0.8、13°、径向分量 0.5 等是实验参数，不是恢复的官机公式。
    相邻 B 任选区按行进方向排列优先级；不能排序原版传感器列表来掩盖差异。
    轮廓与容错仍需更多自由形状/真实游玩验证，参考集含参与校准的数据。

  IntervalJudge.cs
    保留原始事件，再按沿路顺序生成 Push=离开-进入，Release=下次进入-离开。
    不硬塞 130/159/175 尾距；首尾没有区域或零长度时明确拒绝距离导出。
    两个控制模型仅将同键 A/B 且几乎同进同出的窗口归成任选组；
    v2 模型额外应用上述独立容错策略，ChoiceWindows 可在报告中检查。
    其他重叠区分割后标明 overlap-split，重叠行为仍是候选策略。
    小于等于三区的短尾、外圈折角相邻三步直线腿有实验性先进入门控。
    连续步骤复用同一传感器需释放后重新进入，防止按住一处消耗多次回环。
    PrototypeReplay 只有输入状态推进，没有 Unity、音效、延迟、计分时钟。

  FanReplay.cs / NativeFanOracle.cs（v2）
    共用 JudgeStep 数据，额外编译 Wi-Fi 的三路输入规则。
    中路末两区的首传感器互通，所有三路完成后下一次更新才进入判定；
    记录 TooLate 分支允许转为 LateGood 的前置条件。
    原版 fan 同时按多个候选时最后一个优先，与普通 slide 的首个优先不同。
    独立 oracle 来自本地 1.70 SlideFan 反编译代码；测试对照原表保留的顺序。
    对自定义多候选区还防止旧子索引泄漏到更短的末尾列表产生越界。
    没有模拟完整计分窗口、autoplay、声音或画面；没有装入游戏。

  Program.cs
    生成三套模型、70 个非 Wi-Fi 原版参考形状和三个 Wi-Fi 分路的对照。
    额外包含多圈、非原版自由路径、D/E、Touch 非 A 终点、零长度等样例。
    Native170.json 仅在对照层读取；数学引擎不按形状套表。
    “统一表基线”列调用 ExperimentalSlideJudge/Unified/SlideTable（含 V 兼容），
    并非关闭开关时的原始实现；数学原型本身不按形状读取原版表。
    引用 OfficialSlideParity 测试项目，是为复用实际解析器与可离线的 Unity
    数学替身；不是给正式游戏增加测试项目依赖。

区域模型参数
  legacy-seeds：复用现有小圆的中心/半径作为控制组，未复用其比例过渡表。
    A 中心半径 440 / 检测半径 80；B 210 / 45；C 55。
  diameter-calibrated：以原版 1-5 的径向 Push/Release 约束候选圆，
    A 中心仍 440 / 半径 116.42124938964844；
    B 中心 215.80862426757812 / 半径 64.49588775634765；
    C 半径 109.31514739990235。
    原版总表长与几何长度略有不同，所以此模型也不是 1-5 全量精确拟合。
  两者的 D/E 均暂沿用当前锚点小圆，未被 ABC 参考数据校准。
  contours-and-choices：A/B 改用上述方向轮廓并启用独立任选容错；
    C、D、E 与 diameter-calibrated 相同，普通 ABC 不额外插入 D/E。

测试内容
  解析直线/圆弧边界、近切点窄穿越、圆并集、多圈重复访问、重复区重新进入；
  不错误合并仅部分重叠的区域；共线拆段不改变判定；
  变半径曲线与独立 Simpson 速度积分对照、加严精度后的区序/边界收敛；
  2432 个旋转/镜像用例、2178 个两种配置的节点对；
  D/E 开关、E8 编号、三路 fan 几何、Touch 适配器、短尾和退化路径；
  非有限坐标、断裂路径、计算预算、200000 帧离线推进零分配；
  只有区序一致的原版参考参与 NextCheck 和随机输入状态回放比较。
  通过数值测试并不意味着区域/计分等同原版，不以修改参考表来消除差异。

v2 增加的验证
  70 个非 Wi-Fi 原版形状 × 8 旋转 × 4 镜像 = 2240 组；
  区组、原表候选优先顺序、跳区门控全部比较；782592 帧针对性输入回放。
  枚举当前/相邻区的同时按压组合、各候选被选中时的松手，而非只随机播放。
  新轮廓另跑 2178 个 ABC/ABCDE 节点对及凹多边形解析求交、重复圆周访问。
  Wi-Fi 8192 组初始状态、131072 帧回放，以及中路末尾、三路完成延迟、
  同时按压的末候选优先、自定义末尾子索引防越界；输入热路径零分配。

结果与剩余差异
  两种圆模型均只有 56/70 个非 Wi-Fi 区序一致，主要缺少原版 A/B、B/C、
  邻接 B 区任选容错；部分 pp/qq 的任选过渡在几何路径上也没有命中。
  v2 新轮廓达到 70/70 非 Wi-Fi 区序、选择顺序和跳区门控一致；
  外圈圆弧尾等待比例与原表一致到双精度舍入范围。
  最大尾等待差从约 161.62 降至 22.38 ms（均以滑行 1000 ms 计算）。
  仍有复合曲线的内部距离/尾等待差异，区序一致不代表完整判定已一致。
  Wi-Fi 的输入控制已经单独验证；普通 ABC 生成几何两侧末端缺少原版
  A4/D5、A6/D6 的 D 备选，不将它们混入 70/70 非 Wi-Fi 结果。
  还需研究复合曲线距离度量、D/E 的完整校准、原版 fan 备选区策略、
  连段的完整时间映射以及 Unity 实机计分。原版 V 兼容保持当前实现。
